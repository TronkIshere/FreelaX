# 04. Migration roadmap

> **Scope amendment (2026-11-01):** FreelaX is a development simulation with no real funds ([SIMULATION_SCOPE](../SIMULATION_SCOPE.md)). Supported environments: LOCAL_SIMULATION and AVALANCHE_FUJI only. **Mainnet is out of scope.** Wherever this document mentions Mainnet, production, audits for launch, key ceremonies or a Mainnet cutover, read it as historical planning; see the amendment table at the end of [04](04-migration-roadmap.md) and the guards in [phase-1/simulation-environment-guards.md](phase-1/simulation-environment-guards.md). Decisions D1 to D4 are unchanged.

Complexity scale: S (days of focused work), M, L, XL. No calendar durations are given because none can be justified from the evidence. Critical path: Phase 1 -> 2 -> 3 -> 4 -> 6 -> Final. Parallel: Phase 2 and Phase 3 (after Phase 1); Phase 5 can start after the Phase 4 neutral API shape is frozen. External dependencies: Fuji AVAX and test USDC, an RPC provider account, a KMS account, a Snowtrace/explorer API key (if needed), an auditor for the contract before Mainnet.

Cross-cutting rules for every phase: Solana source is not edited except to wire the neutral port; persisted enums unchanged; each phase ends with an explicit review before the next starts.

Decisions: gateway as separate service (mirrors Solana) vs library: the plan assumes separate service for symmetry; confirm. 10. Security: KMS keys non-exportable, startup guards forbidding local signer on mainnet chain id, no plaintext keys, redact RPC URLs in logs. 11. Testing: unit tests; anvil-based integration; Fuji smoke; fault injection for RPC timeouts, nonce conflicts, replacements. 12. Deliverables: buildable module, OpenAPI/endpoint doc. 13. Risks: web3j dependency conflicts; KMS signature conversion. 15. Rollback: remove module entry. 16. Out of scope: contracts, marketplace wiring. Complexity: L.

Modules: `avalanche-contracts/`. 6. New: `src/`, `test/`, `script/`. 7. Existing: none. 8. Dependencies: OpenZeppelin 5.7.0 (verify), Solidity 0.8.38 (verify), EVM `cancun` unless Phase 1 shows otherwise. 9. Decisions: roles and the co-signing replacement are decided in principle (D3, [03](03-target-architecture.md) sections 7 and 9); open: arbiter snapshot vs role, revision co-sign, payout under USDC blacklist, upgradeability (proposed: none), shared vs factory (gate). 10. Security: external review before Mainnet, multisig admin, emergency pause semantic defined, USDC freeze scenarios tested. 11. Testing: fuzz, invariants, fork tests against Fuji USDC. 12. Deliverables: contract, tests, Fuji deployment. 13. Acceptance: all tests green; Slither clean or triaged; every row of the Anchor-to-Solidity mapping in [03](03-target-architecture.md) section 7 has a test, including exact timing boundaries (`now <= delivery_due_at` for submit, `now > delivery_due_at` for dispute from Funded, `now < review_due_at` for revision and dispute, `now >= review_due_at` for release), the 24-168h and `max_revisions <= 2` bounds, one extension of at most 7 days, high-value grace, and no unilateral refund; `release` is callable by any account once eligible and fails on a Disputed escrow; `resolveDispute` works only for the arbiter on Disputed escrows with a non-zero hash; pause blocks only new funding; the backend authorization signer cannot move funds, resolve disputes or change roles (negative tests); EIP-712 signatures fail across a different chain id, contract, escrow, action, nonce or expired deadline; invariants from [03](03-target-architecture.md) section 10 hold under fuzzing; no function lets any role withdraw escrowed funds outside the defined release, refund and resolution paths. 14. Risks: logic divergence from Anchor semantics, USDC upgrade. 15. Rollback: undeployed contracts are discarded; deployed Fuji versions are disposable; a pause path exists for production. 16. Out of scope: backend, frontend, fee logic on-chain. Complexity: L-XL.
