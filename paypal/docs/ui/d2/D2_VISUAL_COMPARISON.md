# D2.2 — Workspace and Review Study Comparison

These observations describe the static compositions for human comparison; they are **not a ranking or a visual QA verdict**. Every study uses the same D2.1 fixture and exactly three representative states. The full six-frame progression remains in D2.1.

| Question | Study A — Rail-First Editorial Workspace | Study B — Document-First Submission Review | Study C — Handoff + Version Ledger |
| --- | --- | --- | --- |
| Workflow continuity | Seven-step horizontal rail is the strongest repeated anchor; current position changes with each state | Compact underlined step indicator keeps chronology near the document heading | Small step line pairs chronology with a separate FROM → TO edge |
| Ownership recognition | Current owner and waiting party sit in the band attached directly to the rail | Owner sits in the document header and decision edge | FROM → TO edge identifies responsibility transfer and current owner |
| Latest submission emphasis | V1 summary is the largest object below the rail/action band on Client review | V1 summary is the largest object in a broad document field | V1 summary leads the main field while handoff stays on the editorial edge |
| Revision feedback prominence | Acid feedback block opens the revision work area above the prospective V2 composer | Feedback becomes the document's lead reading item before V2 fields | Feedback opens the main field, with the handoff edge indicating Client → Freelancer |
| History continuity | Lower ruled history section sits after the current work object | History is a narrow ruled footnote beneath document and decisions | Lower version ledger uses version, status/time, and evidence columns |
| CTA hierarchy | Ink primary CTA sits in the rail's owner/action band; revision decision is outlined | Ink approval sits on document decision edge; revision is secondary beside it | Ink action sits on a ruled line after current work; revision remains outlined |
| Editorial identity | Broad work field, hard rules, large headings, high-contrast rail | Document-like hierarchy with oversized current work and restrained metadata | Asymmetric editorial margin and ledger-style version evidence |
| D1 DNA compatibility | Uses Cream canvas, Ink rules, selective Vermilion/Acid, and stable work-first hierarchy | Keeps work title and document leading, with bounded semantic accents | Keeps strong type and ruled facts while translating density into handoff evidence |
| Anti-SaaS | No floating ownership sidebar or cards; the action band belongs to the document flow | No dashboard panels; owner and decision are attached to the document | Edge and ledger are ruled page structures rather than admin widgets |
| Density | Full rail consumes more vertical attention; brief and history remain compact | Current content receives most space; history is highly compressed | Main field and lower ledger balance current work with more structured history |
| Scalability | Additional versions extend the lower history without altering rail meaning | Long history would extend the footnote/ledger after the current document | Additional version rows fit the ledger, while the newest version remains above |
| Motion readiness | Rail marker, owner band, and CTA are explicit confirmed-transition targets | Document heading, decision edge, and footnote insertion are transition targets | Handoff edge, action line, rail step, and ledger insertion are transition targets |
| Reduced-motion clarity | Static rail marker, written owner, action, and history retain meaning | Document order and labels retain meaning with no motion | FROM → TO edge and ledger remain readable with no movement |
